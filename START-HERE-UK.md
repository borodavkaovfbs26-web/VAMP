# VAMP — наступна інтеграційна версія

Цей пакет підготовлено під наявний Supabase-проєкт VAMP, структуру якого ми перевірили разом у чаті. Він не видаляє наявні таблиці.

## Що вже є в цій версії
- окремі входи й маршрутизація для student / teacher / admin;
- профіль, словник, навчальні теми A1–C1 (поки стартова бібліотека), тести та збереження прогресу;
- домашні завдання та надсилання відповідей;
- список уроків, запити на перенесення та базовий 1:1 відеопрототип;
- адміністративний екран зі списком користувачів, створенням акаунтів через Edge Function і призначенням уроків;
- повідомлення адаптовані до фактичних полів наявної таблиці `messages` (`recipient_id`, `content`);
- екран уроків адаптовано до фактичного поля `lessons.lesson_date`.

## Дуже важливо перед запуском
Це інтеграційна основа, а не готова до комерційного запуску школа. Не завантажуй її поверх робочого сайту, доки не зроблено резервну копію GitHub-репозиторію та Supabase.

## Крок 1. Зроби резервну копію
1. У GitHub відкрий репозиторій VAMP і завантаж ZIP поточної версії через Code → Download ZIP.
2. У Supabase створи резервну копію бази (або експортуй SQL/таблиці, доступним для твого плану способом).
3. Не публікуй `service_role` key. Він ніколи не має бути у браузерному JavaScript.

## Крок 2. Застосуй міграцію до наявної бази
Файл `VAMP-EXISTING-DB-MIGRATION.sql` створює допоміжні таблиці `task_submissions`, `lesson_progress`, `lesson_requests`, функції-перевірки ролей та політики для оцінок, розкладу, уроків, повідомлень і завдань.

Перед запуском переконайся, що резервна копія є. Потім у Supabase → SQL Editor встав увесь файл і натисни Run. Якщо буде будь-яка помилка — зупинись і надішли її, не запускай частини навмання.

Міграція виходить із фактичної структури таблиць, яку ти надсилала. Вона замінює старі політики `tasks` на рольові правила, але не видаляє самі завдання.

## Крок 3. Підготуй сайт
1. Розпакуй цей ZIP.
2. Відкрий папку `VAMP-main`.
3. Завантаж вміст папки в корінь GitHub-репозиторію (не завантажуй ZIP як один файл).
4. Збережи чинний `supabase.js` з URL та publishable key твого проєкту. Не замінюй його на чужий ключ.
5. Перевір, що GitHub Pages налаштований на `main` та `/root`.

## Крок 4. Створення акаунтів
Для створення учнів і викладачів з адмінпанелі потрібна Edge Function `create-user`. Інструкція та код функції є в `SETUP.md` і `supabase/functions/create-user/index.ts`.

У Supabase Dashboard → Edge Functions → Secrets додай серверні секрети, зокрема `SUPABASE_SERVICE_ROLE_KEY`. Не вставляй service-role ключ у `supabase.js`, `app.js`, HTML або GitHub.

## Відомі обмеження — наступні етапи розробки
- відео — лише базовий 1:1 WebRTC прототип; потрібні TURN, а для групових уроків — SFU/медіасервер;
- наразі немає повноцінної інтерактивної дошки, запису занять, групових кімнат і демонстрації екрана;
- граматика A1–C1 — невелика стартова добірка, а не повна програма сотень уроків;
- немає повноцінного білінгу, оплат, тарифів, балансу занять, батьківського кабінету, мобільного застосунку та AI-перевірки;
- у повідомленнях адресат поки вводиться за ID; треба додати контактний список;
- потрібно пройти повний тест ролей на окремих тестових акаунтах student, teacher та admin;
- потрібні резервні копії, журнал аудиту, відновлення пароля, підтвердження email/телефону та додаткові гарантії захисту неповнолітніх.

## Як тестувати без ризику
Створи тестові акаунти, не використовуй реальні дані дітей на етапі тестування. Перевір: вхід кожної ролі, власні дані учня, доступ учителя лише до призначених учнів, адмінський перегляд, створення завдання, відправлення відповіді, оцінку, повідомлення та запит перенесення.
